# Small mlfow pipeline

## Discalmer
Данный мини пет-проект создан, чтобы продемонстрировать владение базовыми навыками MLFlow, Docker и Kubernetes в контексте MLOps. Для демонстрации экспериментов и логирования взяты модели и параметры из другого моего пет-проекта (вставить ссылку) - за более подробным исследованием датасета и моделей следует перейти туда. Для Kubernetes используется Minikube.

Данная ветка проекта фокусируется на Docker и Kubernetes (в самом простом виде). Также есть ветка, которая фокусируется на локальной разработке с DVC и Apache Airflow.

## Краткое описание выбранного датасета и задачи 
Для проекта я выбрал датасет по [проектам Kaggle](https://www.kaggle.com/datasets/codename007/funding-successful-projects). Задача состоит в бинарной классификации успеха проекта по различным признакам. В данном проекте не будет приведен EDA, feature engineering, подбор, оптимизация моделей и тд - всё это можно посмотреть в оригинальном проекте по ссылке выше.

## Описание использованных алгоритмов и технологий
- В данном проекте бинарная классификаиця строится с помощью двух моделей - логистической регресии и LightGBM бустинга (лучшие из исследования).
- Метрики экспериментов логируются с помощью MLFlow.
- Далее лучшая модель продвигается в production и используется для предсказания успеха проекта через app.
- В данной версии mlflow и app запущены в одном контейнере.
- Схема работы - проводим эксперименты с моделями, продвигаем лучшую модель и потом запускаем приложение (с конфигурацией ingress) и делаем запрос через curl или Postman.
- Изменения в проекте и данных отслеживаются с помощью git и dvc.

## Инструкции по запуску проекта для экспериментов с моделями
1) Установить нужные библиотеки из requirements.txt.
2) Установить нужный софт для LightGBM, прописав команду (Ubuntu / Debian / WSL с Ubuntu) `sudo apt install -y libgomp1`
3) Если ещё не инициализированы git и dvc - `git init` и `dvc init`

## Инструкции по запуску приложения app
1) (Нужен установленный Docker) Собираем образы mlflow сервера `docker build -f .\configs\mlflow\Dockerfile -t mlflow-server:latest .` и приложения app `docker build -f .\configs\app\Dockerfile -t kickstarter-app:latest .`.
2) Пушим образ в dockerhub или загружаем в minikube с помощью load, но будет дольше. Для примера: `docker tag mlflow-server:latest greytune/mlflow-server:latest` и `docker push greytune/mlflow-server:latest`.
3) (Нужен установленный Minikube) Запускаем minikube `minikube start --memory=6096 --cpus=2`
4) Деплоим mlflow server (предварительно нужно заменить название образа в зависимости от способа на 2 шаге) `kubectl apply -f .\configs\mlflow\mlflow-deployment.yaml` - ждём 5-10 минут пока всё запуститься и просчитается. Для удобства тестирования внутри сразу обучаются две модели с оптимальными параметрами, чтобы даже без экспериментов можно было работать.
5) Деплоим приложение (предварительно нужно заменить название образа в зависимости от способа на 2 шаге) `kubectl apply -f .\configs\app\app-deployment.yaml `. Ждём минут 5 пока запуститься.
6) Загружаем ingress `minikube addons enable ingress` и применяем конфиг `kubectl apply -f configs/ingress.yaml`. Открываем адрес `minikube tunnel`.

**Disclaimer:** app не обновляется при появлении новой лучшей модели, так как он загружает лучшую доступную модель при запуске - для этого нужно внутри контейнера с mlflow запустить python файл promote_best_model.py и пересоздать приложение.

## Команды для воспроизведения экспериментов
Перед запуском экспериментов, нужно запустить сделать 4 шаг в инструкции по запуску и открыть порт для общения с сервером по localhost, например с помощью `kubectl port-forward svc/mlflow-service 5000:5000 `.
1) Через DVC: `dvc repro --force`
2) Через Airflow:
  - Установливаем переменную AIRFLOW_HOME `export AIRFLOW_HOME=/путь/к/моему/проекту/airflow`
  - Запускаем в bash `airflow standalone`
  - Входим под предоставленной учеткой на localhost
  - Запускаем эксперимент
3) После всех экспериментов нужно запусть файл продвижения лучшей модели `python scripts/promote_best_model.py` внутри контейнера с mlflow сервером.

**Disclaimer:** если запускать проект через WSL, то вероятно будут проблемы с доступом в Airflow. Решение проблемы замороченное, поэтому здесь я его не описываю.

## Работа с приложением
После получения адреса можно посылать приложению запросы по адресу `http://полученный_адрес/predict` запросы в виде json файла содержащие данные о kickstarter проекте (поля должны быть те же, что и в оригинальном датасете). В ответ будет приходить json с предсказанной меткой успеха (1 - успех, 0 - провал) и соответсвующие вероятности.
